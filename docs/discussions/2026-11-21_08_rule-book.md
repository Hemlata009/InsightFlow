# 2026-11-21 · Discussion 08: Step 2, data dictionary and business rules

## Request
"Yes": go ahead with Step 2 (the rule book).

## Decisions
- Three-layer config: `default.yaml` (generic) → `domains/sales.yaml` (sales) → `datasets/<ID>.yaml`
  (per dataset), plus `locales.yaml`. Later layers override earlier ones; lists are replaced, dicts merged.
- Columns and rules are keyed by name (not lists) so a dataset can override one field of one column.
- 13 business rules recorded in [../data-dictionary.md](../data-dictionary.md). The main ones:
  a row is an order line, key = Order_ID + Product, discount is a fraction ≤ 0.8, returns only when allowed,
  negative profit is valid, never convert currency, never guess ambiguous dates.
- Missing-value policies per column: quarantine / keep_and_flag / derive (from the sales formula).
- Unknown YAML keys are errors (Pydantic `extra="forbid"`), so typos can't silently do nothing.

## Simple explanation
The rule book is like a circuit's spec sheet, in three layers: general wiring rules, then the rules for
this kind of circuit, then the settings for this one board. The program reads the sheet; nobody writes
rules inside the program. A rule book with a mistake in it (for example "minimum 0.9, maximum 0.8") is
refused before it can do any harm.

## Technical explanation
- `src/insightflow/config.py`: Pydantic v2 models `DatasetConfig`, `ColumnSpec`, `RuleSpec`, `LocaleSpec`,
  `Policies`, `DuplicatePolicy`, `Business`, `DateRange`. Cross-field validation: min ≤ max, numeric-only
  ranges, rules and the duplicate key must reference existing columns, no alias shared by two columns.
- `normalize_header()`: lower-case, `[^a-z0-9]+` → `_`. `header_map()` / `canonical_name()` for Step 5.
- Rule kinds (evaluated in Step 7): `formula`, `same_sign`, `not_equal`, `date_range`.
- Tests (`tests/test_config.py`, 19): both configs load; locale resolution; dataset overrides domain;
  every messy header of both datasets maps to its canonical column; **the truth data obeys the rule book**
  (allowed values, ranges, date range, returns); 5 kinds of broken config are rejected; unknown locale and
  missing config fail clearly. Total: 68 passing.

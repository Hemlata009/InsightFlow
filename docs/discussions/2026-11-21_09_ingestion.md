# 2026-11-21 · Discussion 09: Step 3, ingestion (safe reader)

## Request
"Do it": build the safe CSV/Excel reader.

## Decisions
- The reader only **reads**. Every cell comes back as text and headers keep their raw spelling.
  Numbers, dates, blanks and header mapping are Step 5's job. The file itself is never changed.
- Each row keeps `_source_row`, its row/line number in the original file, for traceability.
- Files that can't be read safely fail with a stable error code (see the table below), so the pipeline,
  MCP tools and the UI can react properly.
- Rows with the wrong number of fields go into `bad_rows` with their row number and the reason. They
  are never silently dropped; the pipeline will quarantine them.
- Same file uploaded twice: noticed by its SHA-256 fingerprint in a `FileRegistry` (JSON file).
- Size limit of 50 MB by default because this PC has little RAM. Reading big files in chunks is deferred.

## Simple explanation
The reader is like the receiving dock in a factory. It checks each delivery: is the box what the label
says? Is it empty, damaged or locked? It finds the packing list (the header), even if it isn't at the
top, and writes down where every item came from. It doesn't open or fix anything. That happens at the next station.

## Error codes
| Code | When |
|---|---|
| not_found | the path doesn't exist |
| unsupported_format | not .csv/.xlsx, or an old .xls workbook |
| empty_file / empty_sheet | 0 bytes, only blank space, or an empty sheet |
| too_large | above `max_file_mb` |
| signature_mismatch | the content doesn't match the extension (an Excel file named .csv, a text file named .xlsx) |
| encrypted_file | password-protected Excel |
| corrupt_file | damaged/truncated workbook, or a zip that isn't a workbook |
| encoding_error | a forced encoding doesn't fit |
| sheet_not_found | the requested sheet doesn't exist |
| no_header_found | no header row in the first 20 rows |
| no_data_rows | a header but no data |

## Technical explanation
- `src/insightflow/ingestion/reader.py`: `read_file(path, known_headers=, options=IngestOptions(...))`
  → `IngestResult(data, metadata, warnings, bad_rows)`.
  - Signature check: ZIP magic for xlsx; OLE magic → `EncryptedPackage` stream = encrypted, else legacy
    xls; NUL bytes / ZIP / OLE in a .csv = mismatch.
  - Encoding: BOM → utf-8-sig; else try strict utf-8, then cp1252; latin-1 fallback with a warning.
  - Delimiter: for `, ; \t |`, parse the first 50 lines and pick the one giving the most rows with the
    same (>1) field count. Quoted Indian numbers like `"1,00,000"` are handled.
  - Header: best match against the known header aliases from the config (≥2 matches); otherwise the
    first row with ≥60% of the widest row filled and no numeric cells.
  - Excel: openpyxl read-only, `data_only=True`; picks the sheet with the best header match (or the most
    data) and warns; datetimes → ISO text; integer floats → `"3"`.
  - Duplicate headers → `name__2`; blank → `unnamed_<n>`; trailing blank header cells are trimmed only
    when no data row uses them.
- `registry.py`: `FileRegistry.register(meta)` → `(is_new, entry)`, atomic JSON write.
- Tests: `tests/test_ingestion.py` (31): real SALES_002 CSV/Excel (Excel content equals CSV),
  SALES_001 cp1252, source rows, raw file unchanged (hash + mtime), 3 encodings, 4 delimiters, duplicate
  and blank headers, leading zeros, header search, ragged rows, multi-sheet, forced/missing sheet, empty
  sheet, Excel dates, every error code, the repeat-upload registry. Total: 99 passing.
- Bugs caught by the tests and fixed: the header finder was too strict next to a ragged row; trailing
  blank header trimming broke a real blank-named column; header text was being stripped (now kept raw).

## Findings (what testing revealed)
### Bugs found and fixed
1. **UTF-16 files were rejected as "binary".** Excel's "Unicode Text" export contains zero bytes, which our signature check treated as binary. Now detected by its BOM.
2. **A European-locale trap:** the fast path for plain numbers would have read `1.234` as one-point-two-three-four in a German dataset (it means 1234). The fast path now runs only for `.`-decimal locales.
3. **`(500-)` became +500**, because two minus markers cancelled out. It's now refused as `conflicting_signs` (also `-(500)`, `--500`).
4. **Excel dates with a time** (`45746.75`) were refused; now accepted.
5. **Output CSVs showed `₹` as `â‚¹` in Excel** (UTF-8 without a BOM). Outputs are now UTF-8 with a BOM.
6. Vague refusal reasons (`unrecognised_date` for everything) are now specific: `missing_year`, `missing_day`, `timezone_not_configured`, `timezone_name_ambiguous`, `unix_timestamp_not_enabled`, `compact_date_not_enabled`, `outside_date_range_or_not_a_date`.

### Behaviour worth knowing (by design)
- **Time zones change dates:** 20:00 UTC on 5 March is 6 March in India. SALES_002 now has `timezone: Asia/Kolkata`; SALES_001 has none, so zoned times there are refused.
- **`$` follows the dataset currency:** a `$` in an Indian dataset is refused; in a Canadian dataset it means CAD.
- **Mean imputation on skewed data** (1, 1, 2, 1, 2, 1, 5000) would have filled ≈715 where ≈1 is typical, so it is refused.
- **Dropping optional columns** between two files of the same dataset now produces a warning.
- Unix timestamps and 8-digit dates are **off by default**, because such numbers are often IDs.
- Formula-looking cells are reported, **not changed** (changing them would alter the data).

## Simple explanation
We tried to break the machine on purpose with every awkward input we could think of: odd file types,
foreign number styles, mixed-up money, dates from other time zones, half-written dates, blanks that
mean zero. Each case is now a test. Six cases did break it, and those are fixed. The rest it already
handled, or now refuses safely with a clear reason.

## Technical explanation
- Reader: `SUPPORTED` + `MEMORY_FACTOR`, `_check_memory()` (psutil, `insufficient_memory`), UTF-16 BOM path,
  `_json_rows()` (json / json-lines, `pd.json_normalize(sep=".")`), `_parquet_rows()` (pyarrow), hidden sheets via
  `sheet_state`, `_build(header_index=, extra_bad=)`.
- `parse_number()` rewritten: currency token table → ISO code vs locale, locale-aware grouping regexes, sign rules,
  `MAX_SIGNIFICANT_DIGITS = 15`. Normalizer fast path guarded by decimal separator and digit count.
- `parse_dates()`: ordered attempts (locale, 2-digit year, extra formats, naive datetimes, tz-aware →
  `tz_convert(policies.timezone)`, Excel serial incl. fraction, Unix s/ms/µs, compact) + `_refusal_reasons()`.
  New policies: `two_digit_years`, `unix_timestamps`, `compact_dates`, `timezone` (validated with zoneinfo; `tzdata` installed).
- Cleaner: `fill_from_group` (`group_by`), `impute` (`impute_method`, `max_skew_for_mean`) with distribution logging.
- Pipeline: `schema_changes` in every result; profiler `formula_like`; writer `utf-8-sig`.
- New packages: `pyarrow`, `tzdata`.
